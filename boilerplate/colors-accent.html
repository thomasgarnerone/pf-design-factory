Oxygen · Color system

One palette, three tiers.

Oxygen colors are organised as a three-tier token pipeline: primitive → semantic → component. Each tier makes different promises about what can change, and for whom. This page is the canonical reference for all three — filter by tier to see what lives there and how it's meant to be used.

Primitives

Raw hues on a non-linear 100 → 800 scale. Named by color, not role. Never referenced directly in product code — they are the material, not the API.

· #107ACA

Semantic

Role-bearing names (brand, danger, positive…) composed from primitives. This is the layer designers and most engineers consume. Swapping a primitive cascades here automatically.

Part-specific aliases (button.solid.brand.background.hover). Lets a single component re-skin without touching its CSS. Built on top of semantic — almost never on primitives.

Primitives — the raw material

Ten primitive hues, each with an 8-step ramp on the 100 → 800 scale (gray adds a 250 half-step) scale (lower is lighter). The 500 step is the canonical mid-tone; ramps are perceptually tuned so 040 can safely carry 130 text.

Primitives are defined in packages/core/src/style/tokens/color.scss under the [data-theme='doctolib2023'] block (exposed as --oxygen-core-<hue>-<step>). They exist to give the semantic tier something concrete to reference — when a designer needs a darker blue for brand-prominent-strong, they don't pick a new hex, they pick the next step down the ramp.

Semantic — role-bearing colors

The pattern is --oxygen-color-semantic-{family}-{prominent|subtle}-{weak|base|strong|stronger}. Every family has two axes of depth: prominent for text / icons / filled controls, subtle for fills / tints / highlights. The weak → stronger ramps are tuned so a subtle-weak background always pairs with a prominent-strong foreground for AA contrast.

This is the layer you should reach for 95% of the time. It survives rebrand, theme swap, dark mode — primitives can shift underneath without a single component edit.

Component — part-specific aliases

Component tokens name a specific part of a specific component in a specific state: action.buttonPrimary.brand.background.default, indicator.alert.background.positive, surface.background.main.base.hover. They're thin aliases on top of semantic tokens — never on primitives directly — which lets a single component re-skin (for example, the vision marketing theme) without touching its CSS.

Oxygen ships ten component families in this tier: action, form, indicator, surface, text, navigation, collection, layout, overlay, visualAsset. Each expands into dozens of part-level tokens (a single button alone contains ~40 states across solid / outlined / ghost × brand / neutral / danger). The three examples below are illustrative, not exhaustive — they're chosen because they show the most common binding patterns: state-driven (action.button), tone-driven (indicator.alert), and variant-driven (indicator.pill).

action

buttons, links, dropdowns, floating toolbars — anything clickable

form

inputs, checkboxes, radios, toggles, sliders, selectable cards

indicator

alerts, pills, badges, spinners, progress bars, steppers, toasts

surface

page backgrounds and borders at every elevation

text

body, header, minor text, selection highlights

navigation

tabs, pagination, sidebar menu, segmented control

collection

list items, table rows and cells

layout

accordion, carousel, collapsible card, divider, story layout

overlay

modal backdrop, drag-and-drop targets

visualAsset

avatar, icon, logo tinting

Three illustrative bindings below — not an exhaustive list

action · button

Solid and outlined buttons across brand / neutral / danger, each with default / hover / pressed / disabled states. The solid-brand path is the most visible:

oxygen-core-blue-500→ semantic.brand.prominent.weak→ action.buttonPrimary.brand.background.default

indicator · alert

Inline feedback banners keyed by tone. Each tone binds three semantic token pairs: background (subtle-weak), border (subtle-strong), label + icon (prominent-strong).

semantic.positive.subtle.weak· semantic.positive.subtle.strong· semantic.positive.prominent.base
Informative — tips and neutral updates
Positive — action completed
Warning — approaching a limit
Danger — action required

indicator · pill

Pills categorise or label content. Every color variant pulls from the same semantic ramp — background from subtle.weak, label from prominent.strong — so an accent pill (alternative1–3) composes exactly like a tonal one.

semantic.{family}.subtle.weak→background · semantic.{family}.prominent.strong→label
